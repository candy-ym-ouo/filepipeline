# 06 · 前端设计（简单界面）

> 前端定位：**简单、可用、零构建**——原生 HTML + CSS + JavaScript 三件套，
> 由 API 进程静态托管（`GET /` 与 `/static/*`）。前端代码不属于 Go 代码，
> **不参与** 2000~2200 行与 20~25 文件的规模统计。

---

## 1. 技术选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 结构 | 单页 `index.html` | 一个页面承载全部功能，简单直接 |
| 样式 | 手写 `style.css` | 无框架，轻量 |
| 逻辑 | 原生 `app.js`（fetch + DOM） | 无构建步骤、无依赖 |
| 托管 | API 进程 `http.FileServer` | 与后端同端口，开箱即用 |

## 4. 功能与交互

### 4.1 上传

1. 选择文件（`<input type="file">`）或拖拽到上传区；
2. 点击"上传"→ `fetch POST /api/v1/files`（FormData）；
3. 显示进度（XMLHttpRequest `upload.onprogress`，简单实现）；
4. 成功 → 提示任务 ID，自动刷新列表并选中新任务；
5. 失败 → 展示错误码与 message（如 413 超限）。

### 4.2 任务列表

- 默认加载 `GET /api/v1/tasks?page=1&page_size=20`；
- 状态筛选按钮 → 追加 `&status=` 参数重新请求；
- 每行显示：ID、原始文件名、大小、状态徽章、创建时间、操作按钮；
- 分页控件（上一页/下一页 + 页码），基于响应 `total/page/page_size`；
- 手动"刷新"按钮 + 每 3s 自动轮询（页面可见时），保持进度实时。

### 4.3 任务详情

- 点击行 → `GET /api/v1/tasks/{id}`；
- 展示基本信息：文件名、大小、SHA-256、状态、阶段、错误信息、扫描判定；
- **阶段时间线**：渲染 `events[]`，每项含阶段名、结果、尝试次数、时间：
  - VALIDATE ✅ → EXTRACT ✅ → SCAN ✅ → DONE ✅
  - 失败项显示 ❌ + 原因；
- 扫描结果卡片：`scan_verdict`（clean=绿色 / infected=红色 / error=橙色）。

### 4.4 重试

- 仅 `FAILED` 状态的行显示"重试"按钮；
- 点击 → `POST /api/v1/tasks/{id}/retry`；
- 成功 → toast 提示"已重新入队"，刷新列表；
- 409 → 提示任务状态已变化，刷新列表。

## 6. API 调用要点（app.js 骨架）

```js
async function uploadFile(file) {
  const fd = new FormData();
  fd.append('file', file);
  const res = await fetch('/api/v1/files', { method: 'POST', body: fd });
  const body = await res.json();
  if (!res.ok) throw new Error(`${body.code}: ${body.message}`);
  return body;                      // task 对象
}

async function listTasks(status, page) {
  const q = new URLSearchParams({ page, page_size: 20 });
  if (status) q.set('status', status);
  const res = await fetch(`/api/v1/tasks?${q}`);
  return res.json();
}

async function getTask(id) {
  return (await fetch(`/api/v1/tasks/${id}`)).json();
}

async function retryTask(id) {
  return (await fetch(`/api/v1/tasks/${id}/retry`, { method: 'POST' })).json();
}
```

## 7. 非目标（YAGNI）

- 不做登录鉴权、不做 WebSocket 推送、不做复杂表格组件；
- 自动轮询即可满足"进度实时性"，无需引入 SSE；
- 样式仅保证清晰可用，不追求视觉精美。
