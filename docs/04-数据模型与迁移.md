# 04 · 数据模型与迁移

> 本文档定义持久化层：数据库选型、表结构、字段说明、索引，以及迁移方案。
> 迁移能力是项目硬性要求之一（"持久化任务并支持迁移"）。

---

## 1. 数据库选型

- **SQLite**（`modernc.org/sqlite`，纯 Go 驱动，无 CGO 依赖）；
- 单文件数据库，默认路径 `./data/pipeline.db`；
- 开启 `journal_mode=WAL` 与 `busy_timeout=5000`，支持 API 与 Worker 双进程并发读写；
- 迁移 SQL 保持标准 SQL 形态，未来可平滑切换 Postgres（需更换驱动与少量类型适配）。

## 2. 表结构

### 2.1 `tasks` — 任务主表

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | TEXT | PK | 任务 ID（`t_` 前缀 + UUID 短码） |
| `filename` | TEXT | NOT NULL | 用户原始文件名（仅展示用） |
| `stored_name` | TEXT | NOT NULL | 落盘随机文件名（`f_<uuid>.<ext>`） |
| `size` | INTEGER | NOT NULL | 文件字节数 |
| `sha256` | TEXT | NOT NULL | 上传时计算的 SHA-256 十六进制 |
| `mime` | TEXT | NOT NULL | 探测/推断的 MIME 类型 |
| `status` | TEXT | NOT NULL | 状态：PENDING/PROCESSING/SUCCEEDED/FAILED/DEAD |
| `stage` | TEXT | NOT NULL | 当前阶段：VALIDATE/EXTRACT/SCAN/DONE |
| `attempts` | INTEGER | NOT NULL DEFAULT 0 | 当前阶段已尝试次数 |
| `max_attempts` | INTEGER | NOT NULL DEFAULT 3 | 阶段最大尝试次数 |
| `retry_count` | INTEGER | NOT NULL DEFAULT 0 | 手动重试累计次数 |
| `error_code` | TEXT | DEFAULT '' | 最终失败错误码 |
| `error_message` | TEXT | DEFAULT '' | 最终失败原因 |
| `callback_url` | TEXT | DEFAULT '' | 业务方回调地址（预留） |
| `callback_token` | TEXT | DEFAULT '' | 回调签名密钥 |
| `waiting_callback` | INTEGER | NOT NULL DEFAULT 0 | 是否处于等待异步回调态（0/1） |
| `extracted_summary` | TEXT | DEFAULT '' | 提取摘要（≤4 KiB，截断标记） |
| `scan_verdict` | TEXT | DEFAULT '' | 扫描判定：clean/infected/error |
| `scan_scanner` | TEXT | DEFAULT '' | 扫描器标识 |
| `scan_at` | TEXT | DEFAULT '' | 扫描时间（RFC3339） |
| `leased_until` | TEXT | DEFAULT '' | 租约到期时间（领取时写入） |
| `next_run_at` | TEXT | NOT NULL | 下次可被领取时间（重试退避依据） |
| `version` | INTEGER | NOT NULL DEFAULT 0 | 乐观锁版本号 |
| `created_at` | TEXT | NOT NULL | 创建时间（RFC3339） |
| `updated_at` | TEXT | NOT NULL | 更新时间（RFC3339） |

**索引**

```sql
CREATE INDEX idx_tasks_status_next ON tasks (status, next_run_at);
CREATE INDEX idx_tasks_stage      ON tasks (stage);
CREATE INDEX idx_tasks_created    ON tasks (created_at DESC);
CREATE INDEX idx_tasks_lease      ON tasks (status, leased_until);
```

- `idx_tasks_status_next`：Worker 轮询主查询（按状态 + 可领取时间）；
- `idx_tasks_lease`：崩溃回收查询（PROCESSING 且租约过期）。

### 2.2 `task_events` — 阶段事件表（审计轨迹）

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `id` | INTEGER | PK AUTOINCREMENT | 自增 ID |
| `task_id` | TEXT | NOT NULL | 任务 ID（FK → tasks.id） |
| `stage` | TEXT | NOT NULL | 阶段：VALIDATE/EXTRACT/SCAN/DONE |
| `status` | TEXT | NOT NULL | 事件结果：SUCCEEDED/FAILED/RETRYING |
| `attempt` | INTEGER | NOT NULL | 该阶段第几次尝试 |
| `message` | TEXT | DEFAULT '' | 事件说明（成功摘要/失败原因） |
| `created_at` | TEXT | NOT NULL | 事件时间（RFC3339） |

**索引**

```sql
CREATE INDEX idx_events_task ON task_events (task_id, created_at);
```

**设计说明**：所有状态变更必须写事件（业务规则 BR-7），事件表是前端"阶段时间线"
与运维排障的唯一事实来源。

### 2.3 `schema_migrations` — 迁移版本表

| 列 | 类型 | 约束 | 说明 |
| --- | --- | --- | --- |
| `version` | INTEGER | PK | 迁移版本号（1, 2, 3 ...） |
| `name` | TEXT | NOT NULL | 迁移名称（文件名） |
| `applied_at` | TEXT | NOT NULL | 应用时间（RFC3339） |

## 3. 迁移方案

### 3.1 设计目标

1. 迁移脚本随二进制内嵌（`go:embed`），部署零外部文件依赖；
2. 按版本号顺序执行，**每个迁移在独立事务中执行**，失败回滚该迁移；
3. 版本表幂等：已应用的版本跳过，可重复执行 `migrate` 不产生副作用；
4. 迁移模块独立分层（`internal/migrate`），API 与 Worker 启动时都会调用（幂等）。

### 3.2 迁移文件清单

| 版本 | 文件名 | 内容 |
| --- | --- | --- |
| 1 | `migrations/001_init.sql` | 创建 `tasks`、`task_events`、`schema_migrations` 及全部索引 |
| 2 | `migrations/002_add_scan_columns.sql` | 增加扫描相关列（`scan_verdict/scan_scanner/scan_at/waiting_callback`） |
| 3 | `migrations/003_add_retry_columns.sql` | 增加重试相关列（`retry_count/max_attempts/next_run_at`） |

> 说明：实际实现时也可将三份合并为一份 `001_init.sql`，但保留多版本结构更能体现
> "支持迁移"能力与增量演进流程；实现阶段按此三版本结构落地。

### 3.3 迁移执行流程

```
migrate.Migrator.Apply(ctx, db)
  1. 若 schema_migrations 不存在则创建（幂等 CREATE TABLE IF NOT EXISTS）
  2. 读取已应用版本集合（SELECT version FROM schema_migrations）
  3. 遍历 embed.FS 中的迁移文件（按文件名排序）
  4. 未应用版本 → BEGIN; 执行 SQL; INSERT INTO schema_migrations; COMMIT
  5. 任一步失败 → ROLLBACK + 返回错误（进程启动中止并打印原因）
```

### 3.4 迁移 SQL 示例（001_init.sql 节选）

```sql
CREATE TABLE IF NOT EXISTS tasks (
  id            TEXT PRIMARY KEY,
  filename      TEXT NOT NULL,
  stored_name   TEXT NOT NULL,
  size          INTEGER NOT NULL,
  sha256        TEXT NOT NULL,
  mime          TEXT NOT NULL,
  status        TEXT NOT NULL,
  stage         TEXT NOT NULL,
  attempts      INTEGER NOT NULL DEFAULT 0,
  version       INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL,
  updated_at    TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS task_events (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  task_id    TEXT NOT NULL,
  stage      TEXT NOT NULL,
  status     TEXT NOT NULL,
  attempt    INTEGER NOT NULL,
  message    TEXT NOT NULL DEFAULT '',
  created_at TEXT NOT NULL
);
```

## 4. 仓库层 SQL 操作清单（internal/repository）

| 操作 | 说明 | 事务 |
| --- | --- | --- |
| `CreateTask` | 插入任务 | 单条 |
| `GetTask` | 按 ID 查询任务 | — |
| `ListTasks` | 状态筛选 + 分页 + 计数 | — |
| `ClaimPending` | 乐观锁领取（UPDATE ... WHERE version） | 单条原子 |
| `CompleteStage` | 阶段成功：推进 stage/status + 写事件 | 同一事务 |
| `FailStage` | 阶段失败：attempts+1，回 PENDING + 退避时间，或置 FAILED + 写事件 | 同一事务 |
| `FinishSuccess` | 终态 SUCCEEDED + 写事件 | 同一事务 |
| `MarkWaitingCallback` | SCAN 异步模式置 waiting_callback=1 | 单条 |
| `ApplyCallback` | 回调到达：写 scan 结果 + 推进阶段 | 同一事务 |
| `ManualRetry` | 手动重试：attempts/retry_count 重置 + 回 PENDING | 同一事务 |
| `ReclaimExpired` | 回收过期租约（崩溃恢复） | 单条批量 |
| `AppendEvent` | 追加事件（独立使用场景） | 单条 |

## 5. 数据生命周期

1. **创建**：API 上传成功 → `CreateTask`（status=PENDING, stage=VALIDATE）；
2. **流转**：Worker 各阶段以事务推进（状态 + 事件强一致）；
3. **终态**：SUCCEEDED / FAILED / DEAD 后不再被任何 UPDATE 命中（SQL 守卫）；
4. **清理**：保留全部历史任务与事件（审计需要），不自动删除；文件存储目录
   由运维按需清理（提供 `storage.Remove` 供扩展）。
