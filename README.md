# Go 文件处理流水线（File Pipeline）

> 一个基于 Go 构建的**文件处理流水线服务**：用户上传文件后，系统自动执行
> **格式校验 → 内容提取 → 扫描回调 → 失败重试** 的完整处理链路，
> 全程任务持久化、多模块分层、支持数据库迁移，并提供 API、后台 Worker、测试与验证能力。

---

## 1. 项目定位

本项目的核心是一个"一次上传、自动流转"的异步文件处理流水线：

```
上传 ──► 格式校验 ──► 内容提取 ──► 扫描回调 ──► 完成 / 失败(可重试)
(UPLOAD)  (VALIDATE)   (EXTRACT)     (SCAN)      (DONE / FAILED)
```

- **上传**：通过 HTTP API 提交文件，落盘并持久化任务记录；
- **格式校验**：校验扩展名、MIME、魔数、大小、完整性（SHA-256）；
- **内容提取**：按格式解析并提取文件内容（文本 / JSON / CSV 等）；
- **扫描回调**：调用外部扫描服务获取安全判定，支持同步返回与异步回调；
- **失败重试**：每个阶段失败自动指数退避重试，超过阈值进入失败态，支持手动重试。

## 2. 核心特性

| 特性 | 说明 |
| --- | --- |
| 异步流水线 | 上传后立即返回，处理由后台 Worker 异步完成 |
| 多模块分层 | `cmd` / `domain` / `repository` / `storage` / `service` / `worker` / `api` / `config` / `migrate` |
| 任务持久化 | SQLite 存储任务与阶段事件，进程重启不丢失 |
| 数据库迁移 | 内嵌 SQL 迁移文件（`embed.FS`），自带版本表与顺序执行 |
| 失败重试 | 每阶段最多 3 次尝试，指数退避 + 抖动，超限进入 FAILED/DEAD |
| 扫描回调 | 支持同步返回与异步回调两种扫描结果回传方式 |
| 幂等处理 | 乐观锁防重复领取，阶段事件防重复执行 |
| 简单前端 | 原生 HTML/CSS/JS 单页：上传、列表、详情、重试 |
| 测试与验证 | 单元测试 + 集成测试，覆盖状态机、校验、提取、仓库、重试、API |

## 3. 技术栈

- **语言**：Go 1.22+
- **数据库**：SQLite（`modernc.org/sqlite`，纯 Go 无 CGO）
- **迁移**：自研轻量迁移模块（`internal/migrate`，内嵌 SQL）
- **HTTP**：标准库 `net/http`（Go 1.22 路由增强），无第三方 Web 框架
- **前端**：原生 HTML + CSS + JavaScript（静态托管，无构建步骤）
- **依赖**：仅 SQLite 驱动 + UUID 生成，保持最小依赖面

## 4. 目录结构

```
code-07/
├── cmd/
│   ├── api/            # API 服务入口（含静态前端托管）
│   └── worker/         # 后台 Worker 入口
├── internal/
│   ├── config/         # 配置加载与校验
│   ├── domain/         # 领域模型：任务、状态机、阶段、错误
│   ├── repository/     # 持久化：任务仓库、事件仓库、工厂
│   ├── storage/        # 文件存储：落盘、读取、校验和
│   ├── service/        # 业务编排：流水线、校验、提取、扫描、重试策略
│   ├── worker/         # 后台调度：轮询、领取、阶段执行、优雅关闭
│   ├── api/            # HTTP 传输层：路由、处理器、中间件
│   └── migrate/        # 数据库迁移：内嵌 SQL、版本管理
├── migrations/         # 迁移 SQL 文件（001_init.sql ...）
├── web/                # 简单前端（index.html / style.css / app.js）
├── docs/               # 项目文档（本目录）
├── go.mod
└── Makefile            # 构建 / 测试 / 验证命令
```

## 5. 快速开始

```bash
# 1. 构建
go build ./...

# 2. 启动 API 服务（默认监听 :8080，自动执行迁移）
go run ./cmd/api

# 3. 启动后台 Worker（本地演示使用内置 mock 扫描器）
PIPE_SCAN_URL=mock://clean go run ./cmd/worker

# 4. 打开前端
open http://127.0.0.1:8080
```

> 提示：不设置 `PIPE_SCAN_URL` 时，Worker 默认调用 `http://127.0.0.1:9090` 的外部扫描服务；
> 本地完整链路演示可使用 `mock://clean`、`mock://infected`、`mock://async` 或 `mock://error`。
> `make verify` 一键执行构建 + 静态检查 + 测试 + 行数/文件数统计。

## 6. API 一览

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/healthz` | 存活检查 |
| `POST` | `/api/v1/files` | 上传文件（multipart），创建处理任务 |
| `GET` | `/api/v1/tasks/:id` | 查询任务详情（含阶段事件） |
| `GET` | `/api/v1/tasks` | 任务列表（状态筛选 + 分页） |
| `POST` | `/api/v1/tasks/:id/retry` | 手动重试失败任务 |
| `POST` | `/api/v1/scan-callback` | 接收外部扫描服务异步回调 |
| `GET` | `/` | 前端页面（静态托管） |

完整接口约定见 [docs/03-API设计.md](docs/03-API设计.md)。

## 8. 硬性验收标准（约束）

1. **功能**：上传 → 格式校验 → 内容提取 → 扫描回调 → 失败重试，链路完整；
2. **架构**：多模块分层，任务持久化，支持数据库迁移；
3. **规模**：非测试 Go 代码行数 **2001 ~ 2199 行**，Go 代码文件数 **21 ~ 24 个**（详见 [docs/07](docs/07-代码结构与规模规划.md)）；
4. **前端**：提供简单可用的前端界面（上传、列表、详情、重试）；
5. **质量**：提供测试与验证命令，`go vet` / `go test ./...` 全部通过。
